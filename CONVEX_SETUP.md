# Convex + Vercel setup

Convex is wired to provision through the **Vercel build**, not a local `convex dev`.
The code is ready; these are the one-time dashboard steps only you can do.

## 1. Create the Convex project (dashboard)
- Go to https://dashboard.convex.dev → **Create Project** (log in with GitHub — the jessaura account).
- Name it (e.g. `jfs-fashion`). This creates a **production** deployment in the cloud.

## 2. Get a deploy key
- In the project → **Settings → Deploy Keys → Generate Production Deploy Key**.
- Copy it (starts with `prod:`).

## 3. Add it to Vercel
- Vercel project → **Settings → Environment Variables**.
- Add `CONVEX_DEPLOY_KEY` = the key from step 2 (Production scope).
- Nothing else needed — `vercel.json` already sets the build command to
  `npx convex deploy --cmd 'npm run build'`, which pushes functions to Convex
  **and** injects `NEXT_PUBLIC_CONVEX_URL` into the Next build automatically.

## 4. Deploy
- Push to `main` → Vercel builds → Convex functions deploy → site goes live.

## 5. Seed the products (once, after first deploy)
- Convex dashboard → **Functions → `seed:seed` → Run**.
- Inserts the 12 products from `src/data/products.ts`. Safe to re-run (no-ops if data exists).

---

### Notes
- `convex/_generated` is gitignored — regenerated by `convex deploy` each build.
- Local `convex/*.ts` files show TS errors for the missing `_generated` imports
  until a deploy runs; that's expected and doesn't affect the Next app.
- Consumers still read from the static `src/data/products.ts`. Migrating them to
  the Convex `products.list` / `getBySlug` queries is the next step once the
  backend is live and seeded.
